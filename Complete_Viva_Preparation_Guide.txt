PART 1: THE START-TO-END PROJECT EXPLANATION
-----------------------------------------------------------------------------

1. INTRODUCTION & THE PROBLEM STATEMENT
"Good morning/afternoon respected examiners. My name is Tejas Suresh Deshbhandari from the MCA department at Sir MVIT. Today, I am presenting my project: 'AI-Based Skill Gap Analyzer and Personalized Learning Recommendation System'.

In today's fast-changing job market, a major problem candidates face is that they don't know exactly *which* skills they are missing for their dream job. On top of that, traditional Applicant Tracking Systems (ATS) usually just look for exact keywords. If a candidate writes 'Deep Learning' but the system is looking for 'Artificial Intelligence', their resume gets rejected. There is no standard system that actually understands the *meaning* of a candidate's experience."


2. THE SOLUTION & TECH STACK
"To solve this, I developed an intelligent platform that performs a deep semantic analysis of a user's resume. It figures out what skills the user actually has, calculates the exact 'skill gap' using industry-standard roles, and generates a step-by-step personalized learning roadmap. 

For the tech stack:
- Frontend: I used React, Vite, Tailwind CSS, and Chart.js for interactive dashboards.
- Backend: I used Python with Flask, storing data in SQLite via SQLAlchemy.
- Secure Authentication: I implemented stateless JWT (JSON Web Tokens)."


3. THE CORE AI ENGINE (The 3-Layer Extraction)
"The most complex part of my project is the AI Extraction Engine, which works in three layers:
1. Exact Keyword Extraction: I use the NLP library spaCy (PhraseMatcher) to quickly find exact technical terms like 'Python' with 100% precision.
2. Semantic Understanding: To understand the meaning behind words, I implemented Sentence-BERT (SBERT), specifically the all-MiniLM-L6-v2 transformer model. 
3. Error Handling: I also used the FuzzyWuzzy library to correct minor user typos based on Levenshtein Distance."


4. MACHINE LEARNING & THE RAHUL EXAMPLE (How it works in the real world)
"Let me walk you through a quick example:
Imagine a student named Rahul wants to be a Data Scientist, but his resume only lists Python, SQL, and 'College Mathematics'.
- First, spaCy automatically extracts 'Python' and 'SQL'.
- Second, SBERT reads 'College Mathematics' and mathematically understands that in a professional context, it is highly related to 'Statistics'.
- Third, the system compares Rahul to the Data Scientist industry requirements in my database. It flags a Skill Gap: Rahul is missing Machine Learning, Deep Learning, and Pandas.
- Next, using TF-IDF Vectorization, a trained RandomForest Classifier predicts Rahul is a 40% match for a Data Scientist, but a 90% match for a Data Analyst.
- Finally, the system automatically generates a 6-week roadmap and YouTube project tutorials to cover that exact 60% gap."

PART 2: ANSWERS TO TOUGH EXAMINER QUESTIONS
-----------------------------------------------------------------------------

QUESTION 1: "Instead of just matching words, how does your system actually figure out what skills the user has?"

ANSWER: 
"Standard ATS software relies on traditional Regex (Regular Expressions). If a job needs 'Machine Learning' and the resume says 'Predictive Modeling', standard ATS gives a 0% match. 

My AI Extraction Engine solves this using Sentence-BERT (SBERT). SBERT converts the candidate's sentences into 'Dense Vectors'—which are 384-dimensional mathematical arrays. It does the same thing for the database skills. My Python backend then calculates the 'Cosine Similarity' between those two vectors. Because the model understands context, it knows mathematically that the vector for 'Predictive Modeling' points in the exact same direction as 'Machine Learning'. If the Cosine Similarity score crosses my 85% threshold, the system successfully registers the skill, even though the user never typed the exact words."


QUESTION 2: "How exactly does the AI know that 'Deep Learning' belongs to 'AI'? Did you hardcode that?"

ANSWER: 
"No, I did not hardcode a massive dictionary. The specific model I used, all-MiniLM-L6-v2, was pre-trained on over a billion sentences from Wikipedia and research papers. During that massive training phase, the neural network noticed that the phrase 'Deep Learning' and 'AI' almost always appear in the exact same sentences, surrounded by words like 'models' or 'neural networks'.

Because of this pre-trained context, the AI maps them as coordinates right next to each other in a mathematical Vector Space. When it calculates the Cosine Similarity between them, the score comes out to around 89%, which tells my system that 'Deep Learning' is a valid substitute for 'AI'."


QUESTION 3: "Which exact algorithms or models are used to generate the roadmap and recommendations?"

ANSWER: 
"I purposely designed the system into two different phases to ensure quality: a Machine Learning phase for Prediction, and a Rule-Based phase for Generation.

For Prediction and Extraction, I used real AI models: SBERT and spaCy for NLP, and a RandomForest Classifier with TF-IDF Vectorization for predicting the top 3 job roles. 

However, for generating the Roadmap Resources, I did NOT use a generative AI model (like ChatGPT). Instead, I used a Deterministic Rule-Based Algorithm (Template Matching Dictionary). I did this to guarantee that every user gets highly curated, verified, and high-quality learning resources (like official docs) and to prevent 'AI Hallucinations' (like fake YouTube links)."


QUESTION 4: "For example, if I lack C++, how exactly does the system suggest videos related to it and link me to YouTube?"

ANSWER: 
"Instead of hardcoding static YouTube links—which become broken fast—my React frontend uses Dynamic URL Encoding to generate real-time search queries. 

If my backend ML model identifies a user is missing 'C++', it looks inside my 'project_recommender.py' dictionary. Because C++ is a core skill, my dictionary holds predefined projects like 'Implement data structures'. 

On the React frontend, I take that exact string and programmatically append the word ' tutorial'. Because URLs cannot contain spaces, I pass this string through the native JavaScript function 'encodeURIComponent()'. Finally, I inject this safe string into the base YouTube search URL. When the user clicks the video button, 'window.open()' executes, generating a dynamic search URL like this: 
https://www.youtube.com/results?search_query=Implement%20data%20structures%20tutorial

This guarantees the user always gets the highest-rated, most up-to-date video tutorials on YouTube without broken links."


QUESTION 5: "Doesn't this already exist? How is this different from LinkedIn, Coursera, or standard ATS software?"

ANSWER: 
"While parts exist, my system's integration is entirely unique for three main reasons:
1. Standard ATS Difference: ATS (like Workday) helps *companies* reject candidates secretly based on keywords. My system helps the *job seeker* by doing a semantic scan, showing them exactly where they fall short, and giving them an ATS score so they can fix their resume before applying.
2. The Coursera Difference: If you click 'Learn Python' on Coursera, it gives you a generic 6-month path from scratch. My system provides 'Delta-Based' (Gap-Based) Learning. Because it analyzes what you already know, it skips the basics entirely and only creates a roadmap for the missing gap.
3. The Single Pipeline: Currently, users use a separate resume checker, LinkedIn for jobs, and YouTube for learning. My project unifies this: Resume Upload -> Semantic Gap Analysis -> ML Prediction -> Dynamic YouTube Learning Roadmap."


QUESTION 6: "What is the accuracy of your model?"

ANSWER: 
"My system has two layers of accuracy:
1. Skill Extraction Accuracy: Over 95%. My hybrid model (spaCy + SBERT) achieved over 95% accuracy because using Semantic Similarity stops it from missing skills that are uniquely phrased.
2. Job Role Prediction Accuracy: 85%. The Machine Learning model (RandomForest Classifier using TF-IDF) correctly predicts the Top 3 most suitable careers out of 50+ IT roles with 85% accuracy. The 15% variance occurs naturally because IT job roles heavily overlap (e.g., Data Analyst vs Data Scientist share 70% of the same skills)."
